# Task019 — simulator and integration reuse audit

**Audit date:** 2026-10-30
**Audit base:** `f8cab8b417fda6f78ab3e22d21cd789a0e8577b5` (workspace commit)
**Scope:** Documentation review of the seven candidates named in `PROJECT_PLAN.md`. The review checked the pinned local Showdown checkout and publicly accessible upstream primary sources. It did not install dependencies, run candidate test suites, benchmark code, or adopt/copy external code.

## Decision

Keep the pinned Pokémon Showdown checkout as the authoritative Gen 5 `gen5randombattle` oracle. There is no inspected candidate with both an available, license-identified implementation and demonstrated fidelity for this exact target that justifies replacing it. Showdown itself covers the reference mechanics, format data, team generation, and protocol. The workspace pins `smogon/pokemon-showdown` at [`1242c1e2d9763ba5b85d33f13aecb89bae19ae3d`](../reference-lock.json); the local checkout matches that SHA and is clean. Upstream `master` had advanced to `ccfaa20f32af363569cd21a9d501b2bc1ded26b1` by the audit date, so continuing to use the local pin keeps the oracle stable.

For the JAX engine foundation, do not adopt an inspected external port. Continue the project’s custom, incremental JAX path provisionally, using pinned Showdown for differential evidence. This is an engineering direction while the JAX mechanics and full transition coverage remain incomplete; it is not a finding that the current JAX code is a complete or validated engine.

The strongest possible component candidate is `poke-env`, as a Python client and player-interface reference. Adopting it would replace or bridge the current in-process TypeScript `BattleStream` harness with a Python/server client path; exact Gen 5 request parsing, player-view fidelity, version matching, and transport cost still need direct differential evidence. Metamon is a possible source of data-format and policy ideas, subject to finding Gen 5 Random Battles data and validating replay reconstruction. The Gen 4 JAX repository may inform implementation and test design, but its generation mismatch and unverified license block reuse decisions. The PokeJAX paper and Jaxcalibur write-up are research evidence, not inspectable source packages. Pgx is general JAX game-environment infrastructure with no identified Pokémon implementation.

License fields below report the repository metadata or license file inspected at the recorded revision. They are not a legal compatibility determination for this project, dependencies, datasets, or trademarks.

## Evidence limits and G0 boundary

- GitHub source links above identify the inspected commit for code repositories. Showdown’s local lock remains the authoritative reference; its current upstream tip is noted only to make drift visible.
- Jaxcalibur’s website and the PokeJAX arXiv paper are primary author sources, not audited source trees. Their reported results are attributed to their authors. Only the PokeJAX paper provides a sufficiently specific hardware/workload description to record rates; those rates do not set this project’s target.
- “No license identified” or “no source repository identified” means the reviewed public material did not establish one. It is not a claim that none exists elsewhere.
- Candidate suites and claims were inspected but not executed or independently reproduced. No full candidate dependency or data-license review was performed.
- This closes the reuse-decision item identified in Task018, but **G0 remains partial**. The mechanics ledger records narrow arithmetic evidence and major absent simulator behavior. A complete Gen 5 transition engine, complete data/team-generation coverage, end-to-end observation/request parity across the required battle scope, and a concrete benchmark charter with fixed workload/resource rules remain open.

## Primary-source evidence notes

- **PokeJAX throughput and fidelity limits:** arXiv 2603.12145v2, §4.1 “Throughput Results,” Table 2 reports `500±9M` steps/s for random actions at JAX batch 65K, `15.2±0.2M` steps/s for PPO, and Showdown reference rates of 21K SPS (one process) and 681 SPS for the Poke-env multi-instance setup. §4 states benchmarks use one RTX 5090. Appendix §A.6 says JAX timing excludes JIT warm-up and gives PokeJAX’s roughly 45-second JIT and about 28 GB memory at batch 65K. Appendix §A.1 describes the Showdown translation and says minor rule-edge modules are excluded. These locations were inspected in the [versioned paper](https://arxiv.org/html/2603.12145v2) on 2026-10-30.
- **PokeJAX generation/format:** Appendix §A.1 and the full v2 HTML identify Showdown as the source, but do not name a Pokémon generation or format. A full-text check for “Gen 5,” “Gen 9,” and “Random Battle” returned no matches. This records what the paper does not specify; it does not infer which generation the implementation used.
- **Jaxcalibur release status:** the author’s [technical write-up](https://jaxcalibur.github.io/) says, “I may also release the code and model weights.” The page was accessed 2026-10-30. This is a conditional statement by the author; it does not establish that source code was publicly released at the audit date.
- **poke-env scope wording:** the inspected [`README.md` at commit `7ff6212`](https://github.com/hsahovic/poke-env/blob/7ff6212e4e738efd46f1ea52035b37a8bba1e386/README.md), opening description, says: “`poke-env` is a Python library for building scripted agents, self-play experiments, and reinforcement learning workflows on Pokemon Showdown.” Its linked Jaxcalibur project example mentions Generation 9 Random Battle, which describes that project and does not establish `poke-env` generation support. The README has no generation-support matrix; exact Gen 5 support remains to be checked against source/tests.
