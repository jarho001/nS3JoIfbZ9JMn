**Coverage meaning:** a row records parity evidence for one pure JAX operation or composition under the documented caller contract. It does not estimate the fraction of Gen 5 mechanics implemented. Composed rows reuse constituent kernels and are not additional atomic mechanics.

All listed operations use strict `int32` numeric inputs, strict boolean flags where applicable, and JAX broadcasting as tested by their Python suites. Domains below are caller preconditions; kernels do not dynamically validate ranges. Each oracle fixture is trusted engineering evidence, not a player observation or policy input. “Ordinary” means initialized pinned Showdown entities and real moves/events for the observed path. “Synthetic” means specifically controlled inputs or event outputs to probe an arithmetic boundary; it is not ordinary battle coverage.

## Accepted restricted simulator slice

Task034 implements the accepted restricted `gen5-neutral-tackle-mew-1v1-v1` slice. It is deliberately separate from the arithmetic-function inventory above and does not add a counted public function or claim full-format mechanics coverage. The fixed-shape [`BattleState`](../simulator/neutral_tackle.py) and pure `transition` use the existing arithmetic kernels for one simultaneous Tackle turn. The strict bounds and exclusions are recorded in the [variant contract](neutral-tackle-variant.md).

The guarded [`neutral-turn-oracle.cjs`](../reference/neutral-turn-oracle.cjs) checks the pinned revision, directly supplies one Mew set per side to the unmodified Gen 5 Random Battle format, captures both live move requests, and submits both Tackle choices through `Battle.makeChoices`. It observes native PRNG calls while delegating every result unchanged. Focused evidence is [`neutral-turn-oracle.test.cjs`](../test/neutral-turn-oracle.test.cjs) 3/3 and [`test_neutral_tackle.py`](../test/test_neutral_tackle.py) 6/6 on CPU, including multiple live seed vectors, both speed orders, critical, surviving continuation, first-action KO, exact native state/draw parity, and recipient-specific views. Task034 was accepted at count34, while G1/G3 and all implementation milestones remain open. No GPU acceptance or performance claim is made.

Task035 implementation is complete pending primary review. [`simulator/neutral_duel.py`](../simulator/neutral_duel.py) adds a pure bounded compiled executor over the same turn kernel, with a static maximum capacity of 56, dynamic per-lane budgets, successful-prefix masking, honest stop/budget diagnostics, and state-based resumption. The explicit [`neutral-turn-oracle.cjs --duels`](../reference/neutral-turn-oracle.cjs) mode captures four actual complete battles of 8, 8, 8, and 1 turns from four distinct seeds; they include both first-action orders, true criticals, surviving turns, and a terminal first-action KO. The new Python differential test compares every state, event/order, draw bound/context/value/pre/post limb, both existing recipient projections, and terminal outcome. Focused evidence: new duel tests 4/4 plus the corrected heterogeneous-lane method 1/1; Node full-duel and unchanged default-oracle tests 5/5; unchanged Task034 JAX tests 6/6. The no-argument oracle output is byte-identical to its pre-edit 124744-byte snapshot (SHA-256 `d1a219a9483d8d1c0859338089a8d980372e79987c796f155e5c210395828157`). Primary accepted Task035; accepted count35 is recorded; no GPU, throughput, full-format, G1/G3 or milestone claim is made.

The accepted target is the complete pinned Showdown `gen5randombattle` game from `smogon/pokemon-showdown` commit `1242c1e2d9763ba5b85d33f13aecb89bae19ae3d`: generation 5 singles with random teams, mod chain `gen5 → gen6 → gen7 → gen8 → base`, no Team Preview, and the declared Obtainable, Sleep Clause Mod, HP Percentage Mod, Cancel Mod, and Illusion Level Mod rules. Operational benchmark choices in the charter—such as suite size, seed roots, statistical precision, hardware, concurrency, and runtime/resource budgets—remain unresolved for future measurements.
